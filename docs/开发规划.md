# AgentMusic 开发规划

## 1. 规划目标

开发目标已经从“做一个基于 Spotify 的音乐 Agent Demo”调整为：

**做一个以站内账号系统为核心、以游客模式为基础入口、以 Spotify 为增强 Provider 的 AI 音乐产品。**

这意味着后续开发顺序要彻底调整：

- 先把“AgentMusic 自己能成立”做出来
- 再把 Spotify 做成增强能力
- 最后再继续扩展语音、多 Provider 和高阶推荐

## 2. 当前现状

### 2.1 已有基础

- 前后端已经接入 Spotify OAuth
- 已有 Spotify 搜索、聚合、推荐、歌单详情等接口
- 已有前端播放器、歌单页、搜索页、Agent 工作台
- 已有 Agent 聊天骨架、推荐历史、反馈记录

### 2.2 当前短板

- 站内账号系统还不存在
- 站内歌单 / 收藏 / 推荐历史尚未形成完整自有体系
- 后端仍以 Spotify 用户态数据为主
- 游客模式还没有正式成型
- 音频策略仍过于依赖 Spotify 预览
- 还没有本地音频导入链路，无法支持用户导入 `m4a` 文件

## 3. 路线原则

1. 先建设站内身份，再接外部身份
2. 先保证未登录 Spotify 也能用，再做增强能力
3. 先做站内数据闭环，再做跨平台导入
4. 先做可控的工具式 Agent，再做复杂 Planner
5. 先明确音频边界，再追求完整播放体验

## 4. 阶段划分

## 阶段 A：统一产品路线与文档

### 目标

把所有“Spotify 是唯一核心”的设计改成“站内核心 + Provider 增强”。

### 交付物

- 项目 README 重写
- 系统设计文档重写
- 开发规划文档重写
- 关键背景文档加路线说明

### 完成标准

- 团队成员不再把 Spotify 误认为唯一账号系统
- 后续实现路线统一以站内账号系统为核心

## 阶段 B：站内账号系统

### 目标

让 AgentMusic 首先成为一个拥有自己用户体系的产品。

### 后端任务

- 新增 `users`、`sessions` 等基础表
- 实现注册 / 登录 / 登出 / 会话校验接口
- 区分游客态和站内用户态
- 为所有站内能力挂接本地用户 ID

### 前端任务

- 增加站内登录与注册入口
- 增加游客态与登录态 UI 分流
- 在页面顶部和 Agent 区展示当前站内身份

### 完成标准

- 用户不登录 Spotify，也能登录 AgentMusic
- Agent 会话、歌单、收藏等能力可以绑定到站内账号

## 阶段 C：游客模式

### 目标

让未登录 Spotify 的用户也能体验完整基础产品。

### 后端任务

- 增加公开目录 API 聚合层
- 将可公开访问的 Provider 能力统一抽象为游客接口
- 将必须用户授权的 Spotify 能力明确隔离

### 前端任务

- 游客模式首页
- 游客可用搜索
- 游客可用公开歌单 / 专辑 / 艺人页
- 对需登录功能提供“登录站内账号”或“连接 Spotify”提示

### 完成标准

- 不登录 Spotify 也能完成搜索、浏览、问 Agent、试听
- 不再出现未登录就整个产品不可用的情况

## 阶段 D：站内歌单与收藏

### 目标

把“我的歌单 / 我的收藏”从 Spotify 用户态迁回 AgentMusic 自己手里。

### 后端任务

- 新增站内歌单表和站内收藏表
- 新增本地音频资源表
- 实现增删改查接口
- 支持通过 `source_type + source_id` 保存外部曲目引用
- 支持通过上传保存本地音频引用与元数据
- 为歌单保存封面、描述、排序和来源标记

### 前端任务

- “我的歌单”改为站内数据优先
- “我的收藏”改为站内数据优先
- 支持从搜索结果、推荐结果里收藏或加入歌单
- 支持导入本地 `m4a` 文件并加入站内曲库
- Library 页面支持站内管理

### 完成标准

- 不连接 Spotify，用户也有真正属于自己的歌单和收藏
- 登录站内账号后，用户能导入本地 `m4a` 文件并把它们加入歌单和播放队列

## 阶段 E：站内个性化推荐

### 目标

在没有 Spotify 用户画像的前提下，也能做第一版个性化。

### 后端任务

- 新增行为埋点：搜索、播放、跳过、收藏、点赞、点踩
- 构建用户偏好摘要
- 将行为、收藏、历史推荐反馈纳入推荐生成
- 为 Agent 提供统一的偏好读取接口

### 前端任务

- 反馈按钮接入推荐历史
- 增加“继续这类推荐”“少来一点这类歌”之类的交互
- 推荐历史页接入站内推荐版本

### 完成标准

- 不连接 Spotify，也能体现基础个性化
- 推荐结果不再完全依赖公开热门内容

## 阶段 F：Spotify 增强模式

### 目标

把 Spotify 从“基础依赖”改造成“增强插件”。

### 后端任务

- 新增 `provider_links`
- 将 Spotify OAuth 绑定到站内用户
- 实现导入 Spotify 歌单、同步收藏、读取 Top Tracks / Top Artists
- 将 Spotify 用户画像作为推荐增强输入

### 前端任务

- 增加“连接 Spotify”入口
- 增加导入歌单和同步收藏入口
- 在 UI 中清晰区分“站内歌单”和“导入歌单”

### 完成标准

- 用户可以不连接 Spotify 正常使用
- 用户连接 Spotify 后能获得明显增强，而不是只是“终于能用了”

## 阶段 G：Agent 强化

### 目标

让 Agent 从“能回话”进化成真正的站内操作入口。

### 后端任务

- 统一 Agent 输入输出协议
- 增强工具链：查找、推荐、建歌单、收藏、播放队列控制
- 统一推荐动作和播放器动作
- 让 Agent 明确感知当前用户模式：
  - 游客
  - 站内账号
  - Spotify 增强

### 前端任务

- 增加更多快捷操作卡片
- 将搜索结果、歌单结果、推荐结果一键交给 Agent
- 优化 Agent 页面和播放器联动

### 完成标准

- Agent 能完成“推荐 / 查询 / 建歌单 / 收藏 / 播放队列控制”五类核心任务

## 阶段 H：音频能力升级

### 目标

解决“不登录 Spotify 到底能不能真正听音乐”的现实问题。

### 第一阶段策略

- 继续支持 Spotify `preview_url`
- 把播放器设计成能处理“部分可试听、部分不可试听”
- 增加本地音频导入能力，MVP 至少支持非 DRM 的 `m4a` 文件

### 第二阶段策略

- 预留本地音频或合法可托管音频接入方案
- 将音频来源抽象为独立层，不与目录元数据耦合
- 在 `m4a` 打通后，再评估补充 `mp3`、`wav`、`flac`

### 完成标准

- 用户能明确知道一首歌是否可试听
- 系统不会把“可看见歌曲”误导成“可完整播放歌曲”

## 5. 推荐开发顺序

建议按下面的先后顺序执行：

1. 文档统一
2. 站内账号系统
3. 游客模式 API
4. 站内歌单 / 收藏
5. 站内行为埋点与个性化推荐
6. Spotify 增强绑定
7. Agent 工具链强化
8. 音频能力扩展

## 6. 下一阶段的具体任务清单

### 6.1 后端优先任务

- 设计 `users`、`sessions`、`provider_links` 数据结构
- 设计 `audio_assets` 数据结构
- 新增本地认证中间件
- 抽象 `catalog service` 与 `provider adapter`
- 抽象 `local media service`
- 抽象站内歌单和收藏服务
- 让 Agent 服务优先读取站内数据，再读取 Provider 增强数据

### 6.2 前端优先任务

- 增加站内登录页或弹层
- 为游客模式设计默认首页
- 将 Library 改为站内库视图
- 对 Spotify 增强能力增加“连接后解锁”提示

### 6.3 文档与规范任务

- 统一接口命名规范
- 统一 Provider 抽象协议
- 写清楚不同模式的权限矩阵

## 7. 风险与应对

### 风险 1：Spotify 预览音频有限

影响：

- 游客模式下可试听内容不完整

应对：

- 把试听作为基础体验，而不是完整音乐承诺
- 尽早抽象独立音频源接口

### 风险 1.5：`m4a` 文件来源复杂

影响：

- 不是所有 `m4a` 都能直接播放，尤其是带 DRM 的文件

应对：

- MVP 明确只承诺支持非 DRM 的本地 `m4a`
- 上传时做格式与可播放性校验

### 风险 2：Spotify 仍被误当成主身份系统

影响：

- 站内数据层迟迟建不起来

应对：

- 强制所有“我的歌单 / 我的收藏 / 我的推荐历史”优先落站内库

### 风险 3：Agent 过早依赖复杂外部画像

影响：

- 不连接 Spotify 时体验明显变差

应对：

- 先做站内行为画像
- 后做 Spotify 增强画像

### 风险 4：未来接入多 Provider 时重构成本高

影响：

- 业务层和 Spotify 字段耦合太深

应对：

- 提前建立 Provider 适配接口和标准化领域模型

## 8. 里程碑定义

### 里程碑 M1：产品能独立成立

- 有站内账号
- 有游客模式
- 有站内歌单 / 收藏
- 有本地 `m4a` 导入能力
- 不依赖 Spotify 登录就能正常用基础功能

### 里程碑 M2：Agent 可真正服务用户

- 能查询
- 能推荐
- 能建歌单
- 能收藏
- 能控制站内播放队列

### 里程碑 M3：Spotify 成为增强插件

- 可连接 Spotify
- 可导入歌单
- 可同步收藏
- 可增强推荐

达到 M3 时，项目才算真正实现“AgentMusic 是自己的产品，Spotify 只是一个增强来源”。
