# AgentMusic 选题分析

## 项目用户/场景（选题背景）
**目标用户：** 音乐爱好者，他们**随时随地**使用 QQ音乐/网易云音乐/Spotify 等主流音乐软件听歌，但由于听歌时需要大量的上下文切换，操作麻烦，导致听歌体验不佳。

**核心场景：**
- 通勤/晚上放松（用户不想手动操作的场景）时，想
  - 用语音快速给出**指向性较强**的听歌目标
  - 如“给我来点我常听的/给我来点香港流行，随机模式/帮我播放xxx歌手的歌/帮我播放xxx歌单”
- 想保存不同时期的推荐歌单（比如“2025 夏天歌单”“失恋治愈歌单”），随时切换回去
- 听歌时听到感兴趣的歌，
  - 快速查看歌手简介、歌词、所在专辑等相关信息
  - 快速将歌曲添加到已有歌单
  - 快速推荐该歌手的歌曲列表
  - 快速推荐该风格的歌曲列表


**用户使用现状**
大部分人直接用 主流音乐软件中的 AI DJ **自动推荐** + **手动创建**播放列表。但他们经常抱怨：AI DJ 推荐的**不能精准命中当下自己想听的歌**、**无法保存多个版本推荐**、**获取自动推荐歌曲的操作仍不够便捷**、想看歌手 bio 或歌词时操作繁琐。

**痛点部分：** 对重度音乐用户来说，QQ音乐/网易云音乐/Spotify 等主流音乐软件 的推荐和操作逻辑越来越“不够聪明”，导致他们每天浪费时间手动调整歌单、切换模式、查找歌手信息。

**痒点部分：** 没有这个 Agent 也能正常使用音乐软件，但有了之后会给用户在作为最能代表用户体验的**操作便捷性、歌曲推荐精准性**上带来明显的提升。

**有没有人已经在解决？解决到什么程度？**
- 国内主流的 QQ音乐/网易云音乐 **智能 Agent 功能不完善**，获取推荐等操作还是要依赖用户手动调整。
- Spotify AI DJ 已解决 60-70%（实时推荐 + 语音），但是需要付费开通 premium 账户才能体验到，并且 Spotify 对于歌单中歌曲的批量管理功能不方便，对于用户来说操作不方便；besides，**Spotify 在国内市场是 inaccessible 的**。
- 结论：国内市场有空白，我们不是完全重复造轮子，而是做“Spotify + 个人智能 Agent”的增强版。

**我们真正要解决的问题：**
- QQ音乐/网易云音乐/Spotify 等主流音乐软件的推荐是“平台级”的，无法深度记住每个用户的**长期**偏好和**历史歌单版本**，无法精确命中每个用户的**即时**听歌偏好需求。
- 操作仍然以点击为主，缺少真正的“对话式”自然语言控制。
- 用户想保留不同时期的推荐，但 Spotify 不支持推荐历史版本管理。

## 项目实现预设

#### 项目实现概述
AgentMusic 是一个 Web 端 AI 增强音乐软件，核心目标是打造一个“会思考、会聊天、能直接操控音乐”的智能音乐 Agent。
软件通过 Spotify Web API 获取歌曲、专辑、歌手信息与推荐，同时利用 Microsoft Semantic Kernel 构建智能 Agent，实现自然语言（可支持语音）控制音乐播放与推荐。

#### 项目预设功能点
**priority 1**
1. 获取歌曲、专辑、歌手元数据
2. 底部固定控制栏功能
   1. 播放 / 暂停 / 上一首 / 下一首
   2. 播放模式切换（顺序 / 列表循环 / 单曲循环 / 随机）
   3. 进度条拖动与实时更新
   4. 音量控制条控制音量
   5. 歌词实时查看与高亮
   6. 播放队列查看与管理（选择播放/添加/删除/清空）
   7. 点击歌手名，进入歌手信息页面查看（Bio、热门歌曲、相关艺术家）
3. 中间主界面为 AI Agent 聊天框
   1. AI Agent 支持手动打字控制/输入
   2. AI Agent 支持语音控制/输入 （浏览器 Web Speech API）
   3. 支持历史聊天记录查看
   4. 获取 Agent 自动生成的推荐歌单
4. 左侧栏
   1. Agent 生成的历史推荐歌单（保留多版历史，可点击切换，可进行管理 [添加、删除等] 、demo可设上限如 10 个以方便测试）
5. 右侧栏
   1. 查看正在播放歌曲信息（封面、歌名、歌手/关于艺人、作词、作曲、编曲、出品方）
6.  Agent 能够根据用户自然语言指令自动执行上述所有操作

**priority 2**

2. 左/右侧栏
   1. 支持一键收起/展开

#### 前提
1. 开发者有 Spotify 账号
2. Spotify API 稳定可用

#### 约束
1. 性能约束：歌单加载（1000 首以内）< 800ms
2. 成本约束：OpenAI 调用可先使用免费apiKey
3. 账号约束：开发者暂未开通 Spotify Premium 用户，可先通过 30 秒预览收听歌曲验证功能
4. 合规约束：遵守 Spotify API 使用条款，不存储完整音频

## 可实现性分析

#### 可实现性检查
1. 现有技术能不能做到？
    能。React + Spotify API + Semantic Kernel Planner + Redis + MySQL 组合完全足够。
2. 数据够不够？
    够。Spotify 提供丰富元数据，我们用缓存 + 懒加载解决。
3. 人力、时间、资源是否支持？
    支持。代码量 10000 行左右。有 Coding Agent 的加持无需很多时间。
4. 伦理 / 安全 / 法律风险？
    低风险。主要注意
   1. Spotify 使用条款（不滥用 API）。
   2. 需要 spotify 账号获取数据（可使用桥接模式，用户无需自己访问）

#### 量化成功标准
1. Agent 指令成功率：≥ 90%，实现用户指令一次即能精准给出反应
2. 歌单加载时间：1000 首以内 ≤ 800ms
3. 历史歌单切换时间：≤ 400ms
4. 用户单次操作时长：比纯用 Spotify 减少至少 40%（自然语言控制如语音 vs 手动点击）
5. 技术指标：Planner 执行延迟 ≤ 1.2 秒，Redis 命中率 ≥ 85%
6. 用户主观指标：测试用户满意度 ≥ 4 / 5（“比 Spotify AI DJ 更好用”）


## 分析总结
AgentMusic 针对的是真实存在的中度痛点：音乐爱好者在听歌时面临的操作繁琐、推荐不够精准、历史歌单无法有效保存的问题。

现有主流音乐软件（QQ音乐、网易云、Spotify）虽有 AI DJ，但仍**无法深度记住用户长期偏好**、**无法精准匹配用户即时听歌偏好**、**不支持历史推荐歌单版本管理**，且操作仍以手动点击为主。

本项目通过 Semantic Kernel 构建智能 Agent，结合**自然语言/语音交互**和**历史歌单管理**，形成差异化竞争优势。技术路线成熟，边界清晰，成功标准可量化，在给定约束下完全可行。

项目定位清晰，具有较强的实用价值和开发可行性。
