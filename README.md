# AgentMusic

AgentMusic 的目标不是做一个只能依赖 Spotify 登录才能工作的播放器，而是做一个以**站内账号系统**为核心、以 **AI 音乐 Agent** 为交互入口、以 **多音乐源 Provider** 为扩展能力的 Web 音乐应用。

## 当前产品定位

项目采用“双层能力”路线：

- 基础层：站内账号、站内歌单、站内收藏、站内推荐、站内播放器、Agent 会话与记忆。
- 增强层：Spotify 作为外部音乐源和外部身份增强源，用于公开目录搜索、导入用户歌单、同步收藏、读取用户画像与播放增强能力。

这意味着：

- 不登录 Spotify，用户也应该能正常使用 AgentMusic 的基础功能。
- 登录 Spotify 后，用户可以解锁“导入与增强”能力，而不是把 Spotify 当作唯一入口。

## 三种使用模式

### 1. 游客模式

不登录任何账号，只使用公开目录与公共内容。

可用：

- 浏览公开歌手、专辑、歌单、分类内容
- 搜索公开音乐元数据
- 与 Agent 进行通用问答和推荐对话
- 听可获得的预览音频

限制：

- 没有“我的歌单 / 我的收藏 / 我的个性化推荐”
- 无法使用 Spotify 用户态接口
- 无法播放 Spotify 全量曲库

### 2. 站内账号模式

登录 AgentMusic 自己的账号系统。

可用：

- 保存站内歌单
- 保存站内收藏
- 导入本地音频文件进入站内曲库
- 基于站内行为构建个性化推荐
- 保存 Agent 会话、推荐历史、反馈记录
- 控制站内播放器与播放队列

### 3. Spotify 增强模式

在站内账号基础上连接 Spotify 账号。

解锁：

- 导入 Spotify 歌单
- 读取 Spotify 收藏和 Top Tracks / Top Artists
- 用 Spotify 用户画像增强推荐
- 使用需要用户授权的 Spotify 能力

## 为什么不能只靠 Client ID / Secret

`client_id` 和 `client_secret` 只能证明“这是你的应用”，不能证明“这是某个 Spotify 用户本人”。

所以：

- 应用级 token 适合做公开搜索、公开目录查询、通用推荐。
- 用户级 token 才能读取 `/me` 资源，才能做“我的歌单 / 我的收藏 / 播放控制”等能力。

## 音频策略

当前和未来都要明确区分这三类音频来源：

1. Spotify 公开预览音频  
   适合做游客模式下的基础试听，但数量有限，且 `preview_url` 并不稳定。

2. 站内自有或合法接入的音频来源  
   这是后续如果要做“不登录 Spotify 也能真正听歌”的核心方向。MVP 需要支持用户导入本地音频，且至少支持 `m4a` 格式。

3. Spotify 用户态播放  
   这属于增强能力，必须依赖 Spotify 用户授权。

结论是：

- 不登录 Spotify，可以做“能用的音乐 Agent”。
- 不登录 Spotify，不能指望完整播放 Spotify 正版全量曲库。
- 不登录 Spotify，如果用户导入了本地 `m4a` 等可播放文件，系统应能通过站内播放器正常播放。

## 推荐的系统主线

项目接下来按下面这条主线推进：

1. 站内账号系统
2. 站内歌单 / 收藏 / 推荐 / 会话 / 反馈
3. 游客模式 API
4. 音乐 Provider 抽象层
5. Spotify 增强接入
6. Agent 编排、记忆与推荐闭环
